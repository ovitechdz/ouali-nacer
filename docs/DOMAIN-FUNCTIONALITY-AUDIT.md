# Domain Functionality Audit — Phase 1

**Reference:** `ovitechdz/ovitech.saas-` @ `f99cd02`
**Method:** read-only source inspection of `src/lib/**`, `src/routes/**`, `server/**`,
`migrations/**`, plus the unit tests listed in §13.
**Question answered:** *what does the product actually compute, store, enforce and
demonstrate — independent of its marketing copy?*

## 1. Executive summary

The reference is a **single-farm, local-first demonstrator**. Its real,
deterministic core is:

- a nutrition recommendation engine (DDNE-REF-0.9) with refusal-on-missing-input;
- a health signal engine (weight loss, BCS, scan staleness, gestation, refusals);
- KPI aggregation (identification, data coverage, ration cost, cover days, ADG);
- ration-sheet aggregation with stock deduction and serve gating;
- a local audit trail (events, health events, recs, weights, sign-offs);
- JSON backup/restore with SHA-256 integrity;
- client-side PDF reports (FR/AR via pdfmake + Amiri).

Everything else falls into three buckets:

1. **Simulated** — RFID scanning, connected devices, energy, climate,
   hydroponics, sync.
2. **Presentation-only** — investor dossier, Startup Algeria label, vision,
   team page.
3. **Scaffold** — server sync, Better Auth, tenant membership, PGlite/Neon.

There is **no AI/ML model** anywhere. The engine is arithmetic and rules.

Two workflow defects matter for parity:

- The only role that can approve a ration is `production`, but **no UI can set
  the role**; the default is `field`. The approve → serve workflow is therefore
  unreachable in a fresh session.
- `syncAll()` is a **status flip**, not a network operation. The real server
  endpoint exists but is never called.

## 2. Nutrition engine (DDNE-REF-0.9)

Source: `src/lib/nutrition-engine.ts` (176 lines), `ENGINE_VERSION` in
`src/lib/types.ts:217`.

### 2.1 Refusal contract

The engine refuses to emit a ration (`ration: null`) when **any** required input
is missing:

| Missing input | Message |
|---|---|
| weight absent / non-finite / ≤ 0 | `poids vif (kg)` |
| BCS absent / non-finite | `note d'état corporel (NEC 1–5)` |
| both forage and concentrate unavailable | `contexte fourrager (aucun lot disponible)` |

Refusal output: `confidence: "insuffisante"`, explanatory notes, `missingInputs`,
and the evidence collected so far. This is the strongest truth-preserving
behaviour in the product and must be preserved.

### 2.2 Formulas

Constants (`nutrition-engine.ts:21–28`):

- `ME_MAINT_COEFF = 0.40`
- `ME_PER_KG_GAIN = 23` MJ/kg
- `ME_PER_KG_MILK = 5` MJ/kg
- `MILK_KG_DEFAULT = 1.1` kg
- `FORAGE_ME = 8.5` MJ/kg
- `CONC_ME = 12.5` MJ/kg
- `FORAGE_CP = 12` %
- `CONC_CP = 18` %

Stage targets (`ADG_TARGET`):

| Stage | Target ADG (kg/d) |
|---|---:|
| agneau | 0.22 |
| croissance | 0.18 |
| engraissement | 0.24 |
| brebis_entretien | 0 |
| brebis_gestation | 0.04 |
| brebis_lactation | 0 |
| belier | 0 |

Computation order:

1. `maintenance = 0.40 × W^0.75`
2. growth energy `= ADG_target × 23` (if > 0)
3. lactation energy `= 1.1 × 5` (lactation only)
4. BCS adjustment: `< 2.5` → `+12 %` of maintenance; `> 4` → `−8 %`
5. `ME_need = max(0.85 × maintenance, maintenance + growth + lactation + BCS_adj)`
6. `DMI_max = W × (young ? 0.038 : 0.032)`; “young” = age < 12 months **or**
   stage in {agneau, croissance, engraissement}
7. concentrate share by stage: default 0.28; engraissement/agneau 0.48;
   lactation 0.38; entretien/bélier 0.18
8. availability overrides: no concentrate → share 0; no forage →
   `min(0.7, share + 0.25)`
9. `DMI = min(DMI_max, ME_need / (share × 12.5 + (1−share) × 8.5))`
   then clamped to `[0.6, DMI_max]`
10. `concentrateKg = round1(DMI × share)`;
    `forageKg = round1(DMI − concentrateKg)`
11. `mineralG = round0(W × 0.35 + (lactation ? 8 : 0))`
12. `waterL = round1(W × 0.09 + (lactation ? 2.5 : 0.8))`
13. `meMj = round1(forage × 8.5 + concentrate × 12.5)`
14. `cpPercent = round1((forage × 12 + concentrate × 18) / max(DMI, 0.1))`

Notes generated by rule:

- low BCS majoration / high BCS reduction;
- concentrate unavailable → 100 % forage warning;
- forage limited → acidosis warning and “fractionner”;
- human execution reminder;
- finishing carcass objective;
- observed ADG < 70 % of target → check parasites/water/trough;
- average confidence when ADG is missing.

Confidence:

- `haute` when `animal.adgKg != null` and the ration is emitted;
- `moyenne` when ADG is missing;
- `insuffisante` on refusal.

Evidence array always includes identity (code + RFID), stage + breed, the
engine version with the explicit line “règles déterministes, non IA”, weight/BCS/
age, maintenance formula, growth/lactation formulas, total ME, DMI ceiling, and
the final ration summary.

### 2.3 Observations and risks

1. **Age dependency:** `ageMonths()` uses the real current date, while the seed
   clock is `2026-08-28`. As real time advances, “young” classification drifts and
   test fixtures can change behaviour. Tests pass today because the seed animals
   are young enough at the current date, but this is not time-stable.
2. **Rounding order:** concentrate is rounded before forage is derived, so the
   sum can differ from `dmi` by ±0.1 kg. Acceptable, but must be documented.
3. **No mineral/water stock deduction:** only forage and concentrate are debited.
4. **No upper bound on total ration per pen** beyond DMI per animal.
5. **Language:** notes and missing-input strings are hard-coded French; they are
   not passed through i18n. This is a real Arabic-first blocker.
6. **No versioned formula registry:** `ENGINE_VERSION` is a constant; changing a
   coefficient silently changes historical reproducibility.

## 3. Health signal engine

Source: `src/lib/health.ts` (97 lines).

Constants:

- `HEALTH_SCAN_STALE_DAYS = 3`
- `HEALTH_WEIGHT_LOSS_RATIO = 0.06`
- `HEALTH_LOW_NEC_ALERT = 2.0`
- `HEALTH_LOW_NEC_WATCH = 2.5`
- `HEALTH_LAMBING_WINDOW_DAYS = 10`

Signals:

| Signal | Rule | Level |
|---|---|---|
| `poids` | latest weight < previous × (1 − 0.06) | alerte |
| `nec` | BCS < 2.0 → alerte; 2.0 ≤ BCS < 2.5 → suivi | alerte / suivi |
| `scan` | no `lastScanAt`, or older than 3 days | suivi |
| `gestation` | parsed gestation remaining ≤ 10 days | suivi |
| `refus` | latest rec exists with `ration === null` | alerte |

Aggregation: highest level wins (`ok < suivi < alerte`). `vetReview = true` if
any signal is `alerte`.

Truth notes:

- This is triage, not diagnosis; the UI says so (`vetReview` badge).
- Gestation parsing depends on free-text notes (`gestationInfo`), which is
  fragile and locale-dependent.
- The scan-staleness rule uses `Date.now()`, not the seed clock, so the demo
  naturally degrades over time.

## 4. KPI engine

Source: `src/lib/kpis.ts` (87 lines).

| KPI | Formula |
|---|---|
| `identifiedPct` | active animals with non-empty RFID / active × 100 |
| `meanW` | mean weight over active animals with weight |
| `meanAdg` | mean ADG over active animals with ADG |
| `recOk` | recs with a ration |
| `recBlock` | recs without a ration |
| `dataDrivenPct` | `recOk / (recOk + recBlock) × 100` |
| `forageNeed` | Σ latest ration forage kg (active animals) |
| `concNeed` | Σ latest ration concentrate kg |
| `rationCost` | Σ(ration kg × lot price) using cheapest available forage/concentrate |
| `forageStock` | Σ stock of `fourrage` + `hybride` lots |
| `coverDays` | `forageStock / forageNeed` (null if need = 0) |
| `missingWeight` | active animals with null weight |
| `lowBcs` | active animals with BCS < 2.5 |
| `staleScan` | active animals with no scan or scan older than **1 day** |
| `pending` | open sync rows |
| `energyAutonomy` | energy snapshot autonomy % |

Important inconsistencies:

- `staleScan` here uses **1 day**, while the health engine uses **3 days**.
  The daily worklist therefore flags animals earlier than the health page.
- `identifiedPct` cannot fail if every seed animal has an RFID; it is not a
  RFID-read success rate.
- `dataDrivenPct` measures engine emission rate, not data quality.
- `coverDays` ignores concentrate, mineral and water.
- KPI series are seeded history; they are not recomputed from the live state.

## 5. Ration sheet and stock

Sources: `src/lib/ration.ts` (120 lines), `src/lib/feed-stock.ts` (52 lines),
`src/lib/store/engine.ts`.

### Sheet

- Groups active animals by pen; rows sorted by code.
- Per row: ration kg, mineral, water, cost, blocked/approved/served flags.
- Per group: totals and counts.
- Coverage: `covered` = active animals with a latest rec that has a ration;
  `blocked` = the rest.
- Pens sorted alphabetically.

### Price selection

`foragePrice` / `concentratePrice` in `src/lib/feed.ts` select the cheapest
available lot of the relevant kind (hybrid included). No weighted average.

### Serve gate

`canServe(rec)` requires, in order:

1. rec exists → else “aucune ration”;
2. `rec.ration` exists → else “refus moteur”;
3. `rec.approvedBy` exists → else “revue humaine requise”;
4. `rec.servedAt` is null → else “déjà distribuée”.

`serveRec` adds a stock check (`feedCovers`) before the atomic transition.
`servePen` simulates the whole batch against a copy of the feed array, then
commits one `set()` containing all rec updates, one aggregated stock deduction,
and one event per served rec.

### Stock deduction

`deductFeed` consumes forage from `fourrage` + `hybride` lots and concentrate
from `concentre` + `hybride` lots, in array order, skipping unavailable/empty
lots. A hybrid lot is consumed by whichever need is processed first in the same
iteration. `feedCovers` mirrors the logic without mutating.

Truth notes:

- mineral and water are computed but never deducted from stock;
- a hybrid lot can be exhausted by forage before concentrate gets a chance;
- no negative-stock guard is needed because `feedCovers` rejects first, but
  `adjustFeedStock` can drive stock to 0 and no further.

## 6. Scan and identity workflow

Source: `src/routes/scan.tsx`, `src/lib/store/animals.ts`.

- Resolution order: exact RFID → code (case-insensitive, numeric suffix match) →
  unknown.
- Special query `ERR` produces `unreadable` with a reason.
- On `ok`: `recordScan` updates `lastScanAt`, writes a `scan` event, returns the
  animal, then the UI prefills weight/BCS/notes.
- On `unknown`: `logScanFailure` writes an `erreur` event with
  “Identité absente du registre”; enrolment form appears.
- On `unreadable`: writes “Signal RFID illisible” with the reason.
- `captureAnimal` validates weight/BCS, appends a weight record, updates the
  animal, writes a `saisie` event.
- `registerAnimal` validates code/RFID uniqueness, creates the animal, appends an
  initial weight record, writes an `identite` event, and queues an outbox record.
- `moveAnimal` updates the pen and writes a `transfert` event.

Truth notes:

- The 900 ms “scanning” delay is cosmetic; no reader is involved.
- The `ERR` path is the only way to see a hardware error, and it is a preset.
- Enrolment allows duplicate RFID only if the code differs? No — both are
  checked (`rfid` and `code`) against existing animals.
- `notes` are capped at 500 characters.

## 7. Review → serve workflow (critical defect)

Intended flow:

```
engine emits ration
  → production user reviews / approves
  → field or production user serves
  → stock debited, event written
```

Actual flow in a fresh session:

1. `seedState()` sets `role: "field"`.
2. `setRole` exists in `core.ts` but **no route or component calls it**
   (verified: only `*.test.ts` call it).
3. `approveRec` returns early unless `role === "production"`
   (`store/engine.ts:151`).
4. `RecCard` hides the approve button unless `role === "production"`
   (`rec-card.tsx:77`).
5. `canServe` requires `approvedBy`, so **no ration can ever be served** through
   the UI.

Consequences:

- The golden path cannot complete in the shipped app without devtools or a
  restored backup with `role: "production"`.
- The `/preuve` and `/label` pages can still show checks as satisfied because
  some checks only look for a ration, not for approval/serve.
- `servePen` and `serveRec` are dead UI paths.

This is a **blocking parity defect**: the rebuild must expose an explicit
authority/role model (or remove the gate and document a single-operator mode).
It must not silently keep a dead workflow.

## 8. Sync semantics

Source: `src/lib/store/sync.ts`, `src/lib/indexed-db-storage.ts`,
`server/routes/api/sync/animals.post.ts`.

What is real:

- Outbox records are written on animal create/update (`animals.ts:1–6`).
- Outbox schema has `mutation_id`, entity, payload, farm, attempts, status.
- Server function performs idempotent upsert with membership check and a
  transaction.
- `sync-apply.ts` SQL is unit-tested.

What is simulated:

- `syncAll()` never reads the outbox, never calls the server, and never drains
  anything. It flips local/pending rows to synced and stamps `lastSyncedAt`.
- `failNextSync` is a no-op switch that returns zeros once.
- `markConflict` / `resolveConflict` are manual UI simulations.
- `syncing` status is never set by code.

What is missing:

- client-side queue drain loop;
- retry with backoff;
- server acknowledgement handling;
- conflict resolution based on server versions;
- per-entity outbox for events/recs/weights/health (only animals are queued);
- auth token plumbing from the client to `syncAnimals`.

Truth label: **sync is a UI demonstration, not a synchronization system.**

## 9. Backup and restore

Source: `src/lib/backup.ts`, `/sync` route.

- Export: full `FarmData`, canonical JSON, SHA-256 checksum, format/version/engine.
- Import: format, version, structure, size caps, checksum, then full replacement.
- Size caps: 50,000 per array, 200,000 total.
- Restore is all-or-nothing and does not merge.
- No encryption, no password, no signature. Integrity only, not authenticity.
- Team photos are **not** included (separate store).
- Outbox is **not** included.

Truth label: **real and useful**, with clear limits.

## 11. PDF reports

Source: `src/lib/pdf-engine.ts`, `rapport-pdf.ts`, `indicateurs-pdf.ts`,
`journal-pdf.ts`, `dossier-pdf.ts`.

- Lazy-loads `pdfmake` and VFS fonts.
- Adds Amiri for Arabic and sets `rtl: ar` per text block.
- Report refs: `OVT-REPORT-01/02/03`, `OVT-DOSSIER`.
- Journal PDF includes a SHA-256 reference line.
- All generation is client-side; failures surface as toast only.
- Warm-up on page mount renders an empty document — wasted work, but improves
  first-click latency.

Truth notes:

- Arabic shaping depends on pdfmake + Amiri; must be regression-tested in the
  rebuild.
- No PDF is stored or auditable after download.
- No server-side generation, so no scheduled reports.

## 15. Rebuild decisions implied by this audit

1. **Keep** the deterministic engine, refusal contract, evidence strings and
   confidence model — translated and versioned.
2. **Keep** the health rules, but unify thresholds and inject a clock.
3. **Keep** the ration sheet, stock deduction and `canServe` gate.
4. **Replace** the role mechanism with an explicit, testable authority model.
5. **Replace** simulated sync with either a real queue drain or a clearly
   labelled local-only mode; do not ship the current half-state.
6. **Complete or remove** auth; never ship unused gates.
7. **Self-host** fonts and PWA assets; remove Grok middleware.
8. **Regenerate** the Arabic-first locale as the default and translate engine
   strings.
9. **Preserve** simulation badges and disclaimers on devices, energy, vision,
   investors and label pages.
10. **Add** tests for routes, RTL, Arabic PDF and offline behaviour.
